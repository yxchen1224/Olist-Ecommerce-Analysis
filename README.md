# Olist 电商客户增长、留存与经营分析

## 1. 项目背景

本项目基于巴西 Olist 电商平台公开数据，围绕客户增长、复购留存、商品结构、物流配送和客户体验等业务问题开展分析。

通过 Python、MySQL 和 Power BI 对多张业务数据表进行清洗、关联、统计和可视化，识别平台经营中可能存在的问题，并提出数据驱动的业务优化建议。

## 2. 项目目标

重点回答以下业务问题：

- 客户增长情况如何？新客户与老客户的订单贡献有什么差异？
- 客户复购表现如何？不同商品类别的复购周期是否存在差异？
- 哪些商品类别贡献了更多订单和销售额？商品结构是否存在优化空间？
- 运费成本占销售额的比例如何？哪些商品类别的运费负担较高？
- 配送延迟是否与客户评价存在关联？哪些地区的配送表现较差？

## 3. 技术栈

- Python：Pandas、数据清洗、客户行为分析、统计分析
- MySQL：数据导入、SQL 查询、客户及商品分析
- Power BI：数据建模、DAX 指标计算、交互式可视化
- Git / GitHub：项目版本管理与成果展示

## 4. 核心分析内容

### 客户增长与复购分析
- 统计真实客户数量及订单分布
- 区分一次性客户和复购客户
- 计算整体复购客户率
- 分析客户购买间隔的均值、中位数及分位数
- 检查异常短购买间隔，并进行敏感性分析

### 商品类别分析
- 比较不同商品类别的订单量和销售额
- 分析商品平均售价和平均运费
- 计算类别运费占销售额比例
- 分析不同商品类别的复购周期及样本量可靠性

### 配送与客户体验分析
- 统计配送延迟订单及延迟率
- 分析严重延迟订单
- 比较不同地区的配送表现
- 对比延迟订单与按时或提前送达订单的平均评价分数

## 5. 主要分析发现

- 平台共有 96,096 名真实客户，观察期内复购客户 2,997 名，整体复购客户率约为 3.12%。
- 客户购买间隔存在明显差异。整体复购间隔中位数约为 28.33 天，但排除不足一天的间隔后，中位数上升至约 68.52 天。
- 不同商品类别的复购周期存在差异，但多数类别的复购样本量较少，需要谨慎解释。
- 平台整体运费约占商品销售额的 17%，部分商品类别的运费负担较高。
- 配送延迟与较低的平均客户评价分数存在关联，但不能据此认定延迟是评价下降的唯一原因。

## 6. 业务建议

1. **客户留存：** 根据客户价值和购买行为进行分层，针对潜在高价值客户设计差异化留存策略。
2. **商品结构：** 综合订单量、销售额、商品售价、运费和客户评价，识别值得重点关注的商品类别。
3. **物流优化：** 优先排查延迟率较高的地区及运费负担较重的商品类别。
4. **客户体验：** 结合配送表现和评价数据，进一步定位影响客户满意度的问题。

## 8. 数据获取与运行说明

### 数据来源
本项目使用公开的 Brazilian E-Commerce Public Dataset by Olist。

原始 CSV 数据未上传至 GitHub，使用者需要自行获取数据，并将以下文件放入项目根目录的 `data/` 文件夹：

- olist_orders_dataset.csv
- olist_order_items_dataset.csv
- olist_customers_dataset.csv
- olist_products_dataset.csv
- olist_order_reviews_dataset.csv

### Python 运行环境
需要安装 Python 和 Pandas：

```bash
pip install pandas
```

进入项目目录后，可以依次运行 `python/` 文件夹中的分析脚本。

### SQL 与 Power BI
SQL 脚本位于 `sql/` 文件夹；Power BI 报告位于 `powerbi/` 文件夹。使用者需要根据本地数据环境调整数据库连接及导入路径。

## 9. 数据与分析局限

- 数据来自历史订单记录，不能直接代表当前电商市场状况。
- 观察期内复购率不等同于月度留存率。
- 部分商品类别的复购样本量较少，类别复购周期需要谨慎解释。
- 数据缺少采购成本、营销费用、人工成本等信息，因此无法计算真实净利润。
- 配送延迟与客户评价之间的关系属于相关性分析，不代表因果关系。

## 10. 项目总结

本项目通过 Python、SQL 和 Power BI 完成从数据读取、数据处理、业务分析到可视化展示的分析流程。

项目重点不只是展示数据指标，而是围绕实际经营问题进行分析，并将分析结果转化为可执行的业务建议。
